# WoW Forever: ежедневный поиск выгодных товаров

Настольное приложение (Python + tkinter, без сторонних библиотек). Каждый вечер (по умолчанию 20:00) или по кнопке
«Выполнить сейчас» оно читает аукцион через официальный API Blizzard, считает чистую прибыль после комиссии и
показывает топ-10, раздел «Вендор → Аукцион» (где купить, расположение вендора, ссылки Wowhead) и отчёт на русском.

## Запуск (Windows)
1. Установите Python 3.10+ с python.org (галочка «tcl/tk and IDLE» включена по умолчанию).
2. Распакуйте папку и выполните `python app.py`. Для проверки интерфейса: `python app.py --demo`.
3. Одним файлом: `build_exe.bat` создаст `dist\ForeverDeals.exe` (я его не собирал; Windows и антивирус могут предупредить
   о неизвестном издателе, это нормально для самосборного exe. Надёжнее запускать `python app.py`).
4. Запуск, когда приложение закрыто: `schedule_windows.bat` (задача Планировщика, 20:00; по готовности HTML-отчёт откроется
   в браузере). Пока окно открыто, оно само запускает поиск вечером, а по готовности поднимается поверх окон.

Данные лежат в `%USERPROFILE%\.forever_deals`: `config.json` (Client Secret в нём открытым текстом; чтобы не хранить,
задайте переменную среды `FD_CLIENT_SECRET`), `vendors.json`, `history.sqlite` (снимки аукциона и журнал сделок),
`reports\*.md` и `*.html` (хранятся последние 30).

При первом запуске без ключей открывается мастер с пошаговой инструкцией. Кнопка «Проверить подключение» в настройках
показывает, на каком шаге (аукцион, предметы) связь не работает.

## Обновление
Кнопка «Обновить приложение» работает и в exe, и при запуске из исходников. При старте приложение тихо проверяет обновления
и подсказывает в строке состояния (отключается `update_check: false` в `config.json`).

**Собранный exe.** Сверяет коммит, из которого собран ваш exe, с последним релизом `windows-latest` на GitHub, по
подтверждению скачивает архив, достаёт из него только `ForeverDeals.exe` и закрывается; маленький скрипт ждёт выхода,
подменяет файл и сам запускает новую версию. Папка с программой должна быть доступна для записи (не `Program Files`).
Если подмена не удалась, новый файл остаётся рядом под именем `ForeverDeals.new.exe`.

**Исходники.** Сверяет последний коммит ветки `main` с установленным (файл `VERSION`), заменяет файлы кода и предлагает
перезапуск. Настройки, вендоры, история и отчёты лежат в `%USERPROFILE%\.forever_deals` и не затрагиваются.
Для приватного репозитория добавьте в `config.json` `"github_token": "…"` (токен с правом чтения).

## Подключение к аукциону (один раз)
1. На developer.battle.net создайте клиента (бесплатно), возьмите Client ID и Secret.
2. «Настройки» → введите их, регион и язык. Нажмите «Найти неймспейс»: приложение перебирает известные варианты.
   **Неймспейс Forever мне подтвердить не удалось**, поэтому если поиск ничего не нашёл, введите неймспейсы вручную
   (аукцион `dynamic-…`, предметы `static-…`) по документации Blizzard.
3. «Реалмы…» покажет ID связанных реалмов, «Аукционы реалма…» — ID аукционов (Alliance, Horde, Blackwater).
4. Если у Forever другие пути, их можно поменять в `config.json` (`auction_path`, `item_path`). Там же ID классов предметов
   (`class_trade`, `class_recipe`, `trade_sub`): по умолчанию они как в Retail и для Forever не подтверждены. Если ни один
   материал не распознан, отчёт покажет предупреждение.

## Аналитика и профессии
Вкладка «Аналитика» — это дашборды. «Общая»: плитки (кандидатов, прибыль в день, сколько вложить в закупку, средняя наценка),
диаграммы прибыли по профессиям, топ-10 товаров и причин отказа, предупреждения. Дальше по вкладке на каждую профессию:
те же плитки, лучшие позиции и таблица всех позиций со статусом. Тот же свод есть в отчёте («Аналитика по профессиям»).
Профессия определяется по подклассу предмета: у рецепта — чей он, у материала — откуда сырьё (ткань → портняжное дело,
руда → горное дело и т. д.). ID подклассов как в Retail и для Forever не подтверждены; поменять можно в `config.json`
(`recipe_prof`, `trade_prof`). Предметы, не попавшие ни в одну профессию, идут в «Прочее».

## Вендоры и расположение
В API Blizzard нет ассортимента NPC, поэтому раздел «Вендор → Аукцион» строится по вашему списку (кнопка «Вендоры…»):
ID предмета, цена, имя вендора, ID NPC, расположение текстом, остаток. ID видны в адресе Wowhead:
`https://www.wowhead.com/forever/item=ID`, `…/npc=ID`. Ссылки на предмет и NPC строятся автоматически; приложение
страницы Wowhead не скачивает, они открываются в браузере. Я не смог открыть страницы раздела `/forever/` и проверить их,
поэтому проверьте, что ссылки ведут на нужные страницы. Быстрее всего — «Вендоры…» → «Вставить список…»: по строке на товар `ссылка_или_ID_предмета ; цена ; вендор ; ссылка_или_ID_NPC ; место ; остаток`.
Импорт из CSV: см. `vendors_template.csv`. Запись покупки в «Сделках…» уменьшает остаток у вендора.

## Как считается
`чистыми = цена_продажи × (1 − комиссия) − закупка − депозит × (1 − вероятность_продажи)`; цена продажи — меньшая из
минимальной и обычной (медиана за 14 дней). Рейтинг — по ожидаемой прибыли в день = продаж/день × доля × чистыми.
Для руд, тканей, трав, кожи и рецептов «закупка» — цена продажи вендору (выгодно ли выставлять вместо вендора).
Комиссия 5% и депозит 5% — гипотезы из Classic Era, их нужно сверить с первым чеком и поправить в настройках.
Продажи в день Blizzard не отдаёт: приложение оценивает их по убыли лотов между прогонами. Отмены и перевыставления
тоже уменьшают количество, поэтому оценка умножается на поправку 0.7 (настройка). Первые 3 дня она неточна и помечена.
Изолированные лоты (меньше 3 шт. на аукционе) отклоняются, чтобы одна завышенная цена не возглавила топ. Если данные
аукциона не менялись с прошлого запуска, дубль снимка не пишется. Комиссия задаётся отдельно для каждого аукциона.
После сбоя автозапуск повторяется через 30 минут без всплывающих окон; причина видна в строке состояния.
Вкладка «Сделки…» нужна, чтобы сверять прогноз с реальными покупками и продажами.
Сутки в истории считаются по UTC.

## Дополнительные возможности

Во вкладке «Аналитика» помимо общей и профессиональных страниц есть:

- **Дефицит** — товары с малым запасом (штук на аукционе ÷ продаж в день) и хорошим спросом.
- **Сброс** — если кто-то выставил много дешёвых лотов: что выкупить и перевыставить по обычной цене, прибыль после комиссии в пределах бюджета на позицию.
- **Крафт** — прибыль изготовления по вашим рецептам. API Blizzard рецептов не отдаёт, поэтому они вносятся кнопкой «Рецепты…» (строка: `ID изделия;кол-во;ID реагента:кол-во,…;профессия;название`) и хранятся в `recipes.json`. Реагент без цены не считается нулём: строка помечается «нет цены».
- **Дизенчант** — выгодно ли купить вещь и распылить. Таблицу выпадения вносите сами в `disenchant.json` (образец — `disenchant_template.json`).
- **Аукционы** — арбитраж между аукционами: купить на одном, продать на другом. Другие аукционы задаются в «Настройках» в формате `ID:название:комиссия%`.

В таблицах топа и дефицита есть колонки «Запас, дн.» и «Выставлять по» (рекомендуемая цена: минимальная на аукционе минус «сбить на», но не ниже цены, при которой остаётся минимальная прибыль).

**Сверка с Wowhead.** Для каждой выгодной позиции, которой нет в вашем списке вендоров, приложение один раз открывает её страницу на Wowhead и смотрит вкладку «Продаётся» (sold-by). Результат хранится в `history.sqlite`, повторно предмет не запрашивается. В метках появляется «у вендора: имя за цену», «вендор: нет» или «вендор: не проверено». «Не проверено» (нет связи, лимит запросов `wowhead_budget`, страница не распознана) не означает «вендора нет»; такие позиции проверятся в следующих запусках. **Разметка страниц Forever мне не подтверждена**, разбор написан по образцу других версий Wowhead и проверен только на тестовом образце. Отключается галкой в настройках (`wowhead_check`).

Кнопки внизу: **График цены** (минимум и средняя рыночная по дням; история копится по снимку за запуск), **Строка поиска (TSM)** (список закупки одной строкой для поиска в аукционе).

**Оповещения.** В «Настройках» укажите Discord webhook и/или токен и ID чата Telegram, кнопка «Проверить оповещение» отправляет тест. После вечернего запуска приходит дайджест топ-3, а при падении цены ниже обычной на заданный процент — отдельное сообщение (один раз в сутки на предмет). Галка «Проверять цены раз в час» запускает лёгкую проверку при открытом окне; она не отмечает дневной запуск и не мешает вечернему.

**Импорт сделок из аддона.** «Сделки…» → «Импорт из аддона…» читает файл SavedVariables (`.lua`). Разбор эвристический: поля угадываются по названиям, перед добавлением показывается число найденных сделок; повторный импорт дубликатов не создаёт.

Ключи `config.json` для этих функций: `compare_houses`, `house_name`, `discord_webhook`, `telegram_token`, `telegram_chat_id`, `hourly_check`, `alert_digest`, `drop_pct`, а в расчёте — `undercut`.

**Не подтверждено для Forever:** пути и неймспейс API, ID классов предметов, формат ссылок Wowhead, комиссия и депозит аукциона, синтаксис строки поиска, формат файлов аддонов.
